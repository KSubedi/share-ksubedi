Instructor Guide

Build Your First AI Voice Agent

July 26, 2026 · 45 minutes · Private teaching notes

Class Promise

Students leave with a working agent they can call and a framework for making it useful, safe, and transferable across platforms.

Keep the class concrete and active. No explanation should run longer than a few minutes before students write, configure, call, test, or repair something. Favor one memorable example over five feature descriptions. Keep measurement discussion brief and tied directly to business outcomes.

Instructor Preparation

Shared Agent Setup

  • Have a clean echowin demo account and callable shared agent ready.
  • Prepare a backup restaurant with a website and accessible menu.
  • Do not preconfigure the ordering or reservation workflows. The class needs to see both failures.

Test Destinations

  • Use a test SMS number as the kitchen destination.
  • Use a test phone number as the manager transfer destination.
  • Prepare an approved OpenTable URL.
  • Never send class tests to a real restaurant or real customer.

Room Check

  • Laptops open and projector visible.
  • Confirm the demo number, speakerphone, kitchen SMS, and manager transfer.
  • Share the student handout before class.
  • Open echowin and a browser window for the volunteer-selected restaurant website.

Teaching Throughline

See itBuild itHear itBreak itFix itTest again

Build one evolving restaurant agent chosen by a volunteer. The restaurant must have a website. Teach each concept only when the shared agent needs its next update: first ordering, then menu knowledge, then reservation routing. Students mirror each pattern in their own agents while all live calls use the shared agent on speakerphone.

Minute-by-Minute Run of Show

0:00 to 4:00

Restaurant Draft Pick

Ask for one volunteer to name a favorite restaurant. The only requirement is that it has a website. Open the site on the projector.
“What should this restaurant agent be able to help with by the end of class?” Steer answers toward orders, menu questions, and reservations.

Identify the restaurant identity, basic facts, menu source, and useful caller outcomes. If the site is unusable, switch to the prepared backup restaurant.

4:00 to 10:00

Build Sprint: publish the imperfect version

  1. Create the shared restaurant agent.
  2. Add its identity and narrow initial scope.
  3. Add the website as approved knowledge.
  4. Write the greeting using identity + capability + invitation.
  5. Add an honest unknown-answer boundary and publish.
“A caller cannot scan backward or visually compare six choices. Every sentence must earn its place.”

Teach only the rules needed now: no more than three choices, one requested detail per turn, short sentences, and the question last. Do not add ordering or reservation workflows yet.

Build on the projector while students mirror the pattern in their own agents.
10:00 to 14:00

Order Challenge: let the first version fail

Choose one volunteer. Privately ask them to place a realistic order. Call the shared agent on speakerphone.
Ask the room to capture the caller’s exact request, the agent’s exact failure, and any unsupported promise.
“Excellent. We found the missing workflow before a customer did. Now we level it up.”

Do not rescue the agent during the call.

14:00 to 23:00

Order Workflow Repair Round

Configure the agent while students apply the same pattern to their own agents:

  1. Ask whether the order is pickup or another supported method.
  2. Collect items, quantities, required options, and special instructions one detail at a time.
  3. Collect the customer’s name and callback number if needed.
  4. Read back the complete order and ask for explicit confirmation.
  5. Send a structured text to the kitchen test number.
  6. Claim only what the messaging tool confirms.
“Your request was sent to the kitchen” is not the same as “Your order was accepted.”
Repeat the exact same order call. Verify the spoken confirmation and inspect the kitchen text.

Do not collect card details. Do not promise preparation time, availability, pricing, allergy safety, or acceptance unless verified.

23:00 to 29:00

Menu Power-Up

  1. Add the approved menu page or menu document.
  2. Tell the agent not to guess when the source is silent.
  3. Prepare one answerable menu question and one unverifiable question.
“Approved truth first. If the answer is missing, say so and offer the next useful action.”
Run both questions against the shared agent. Students update their own knowledge and unknown-answer behavior.

For allergy or dietary questions, use only approved information and route uncertain cases to a human.

29:00 to 33:00

Break the Bot: 12-Person Reservation

Choose one volunteer. Privately ask them to request a reservation for 12 people. Put the call on speakerphone.
Ask the room to identify the exact point where the workflow breaks and what information the agent failed to collect.
“Do not fix every bad call by making the prompt longer. This agent needs a real routing rule.”
33:00 to 40:00

Reservation Routing Repair

Configure the agent to ask for party size, desired date, desired time, name, and callback number, one detail at a time.

Party sizeRoute
1 to 4 guestsText the approved OpenTable link. Do not claim a booking exists.
5 or more guestsTransfer to the manager with the collected context.
Transfer failsPreserve the details and offer a manager callback.
“Warm transfer means reason + collected context + confirmed destination.”

Use 5 or more so the boundary case of exactly five is defined. Students add a comparable deterministic route and fallback to their own agents.

40:00 to 43:00

Final Boss Retest

Have the same volunteer repeat the exact 12-person request.
“Did the agent gather the details, route to the manager with context, and avoid inventing a reservation?”

If time permits, test the 1-to-4 guest branch and verify that the OpenTable link is texted.

43:00 to 45:00

Close with visible progress

“What changed between the first calls and the repaired calls?”

Name the two upgrades: the order became a confirmed structured kitchen message, and the reservation became deterministic small-party or large-party routing.

“A production voice agent succeeds on the normal call, fails safely on the unusual call, and hands off cleanly on the call it should not handle.”

48-hour challenge: run five more tests, include two adversarial tests, and improve one repeated failure.

Facilitation Rhythm

Explain Briefly

Teach one principle in plain language and connect it to a call students just heard or are about to make.

Make It Visible

Model the exact change on the projector. Keep the current sprint steps visible.

Stop Talking

Give students quiet time to type, configure, publish, and call. Walk the room instead of narrating continuously.

Debrief the Evidence

Ask what happened in the call, identify the layer that failed, and make the smallest useful repair.

Knowledge Grounding

Source Hierarchy

  1. Structured system of record
  2. Approved policy document
  3. Curated FAQ
  4. Approved website
  5. Human escalation
  6. Never guess

Model Response

Caller: “Is the peanut sauce safe for a severe peanut allergy?”

Agent: “The approved menu does not verify allergen safety. I can connect you with the restaurant so a staff member can confirm.”

Remind students that stale knowledge can be worse than missing knowledge. Production sources need an owner and a review date.

Failure Diagnosis

FailureLikely fix
RecognitionPronunciation, noise handling, confirmation
ReasoningClearer instructions or narrower scope
KnowledgeAdd, correct, or retire an approved source
ToolFix schema, authentication, timeout, or API behavior
ConversationShorten wording or improve repair behavior
PolicyAdd a guardrail, verification step, or escalation

Legal and Safety Wording

  • AI disclosure: teach transparent identity as a strong default. Explain that requirements depend on call direction, purpose, and jurisdiction.
  • Recording: do not teach a memorized state count. Interstate calls can involve conflicting laws. Use conspicuous notice and consent based on legal review.
  • Healthcare: if protected health information is involved, verify the vendor chain, execute required business associate agreements, minimize access, and validate safeguards.
  • Outbound calling: the FCC classifies AI-generated voices as artificial or prerecorded voices for TCPA purposes. Avoid turning this class into legal advice.

Multilingual Quality

Say: “Language availability is a checkbox. Language accuracy is a test plan.”

Test accent variation, regional vocabulary, names, addresses, dates, numbers, code-switching, tool arguments after interpretation, and the availability of a matching human handoff.

Contingency Plan

If the demo fails

Use the failure as evidence, identify the failed layer, and continue with the smallest repair. Keep screenshots of the kitchen message and reservation routes as backup.

If students fall behind

Keep the order confirmation plus kitchen text, then keep the 12-person reservation transfer. Skip extra questions before cutting either retest.

If questions consume time

Park platform comparisons and advanced integrations until after the hands-on build.
