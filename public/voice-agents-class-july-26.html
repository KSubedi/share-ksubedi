About This Workshop

Build a working AI voice agent from the opening minutes of class. Each short concept is followed by an immediate update to your agent, a live call, or a hands-on challenge. You will learn instruction design, knowledge grounding, routing, safe failure, and human handoff by using them.

The hands-on build uses echowin, but the mental models transfer to Vapi, Retell, Synthflow, Bland, and other platforms.

What You Will Learn

🧱 Separate instructions, knowledge, tools, and channels
🗣️ Write concise, phone-first conversations
🔀 Route calls and preserve context in handoffs
🛡️ Add confirmations, boundaries, and safe failure paths
🔨 Build and call a working agent
💼 Package voice agents around business outcomes

The Core Mental Model

Instructions→Knowledge→Tools→Channels

Instructions

How the agent behaves, what it asks, and where its authority ends.

Knowledge

Approved facts it may use. Missing information should produce an honest boundary, not a guess.

Tools

Actions such as booking, lookup, messaging, and transfer, each with the smallest useful permission.

Channels

Phone, chat, SMS, or WhatsApp. The same agent may need different behavior in each channel.

Hands-On Course Plan

How the class works: one volunteer chooses a favorite restaurant with a website. Together we build one shared restaurant agent, let it fail at two real jobs, repair it, and repeat the exact calls. You apply each lesson to your own agent as we go.
0:00 to 4:00

🍽️ Restaurant Draft Pick

  • A volunteer names a favorite restaurant.
  • The only requirement is that the restaurant has a website.
  • We open the site and identify the restaurant, its basic facts, its menu source, and the caller outcomes worth handling.
Today’s mission: take and confirm an order, send it to the kitchen by text, answer menu questions, and route reservation requests safely.
4:00 to 10:00

🛠️ Build Sprint: The Imperfect First Version

  • Create the restaurant agent in echowin.
  • Add identity, a narrow initial scope, the website, and an honest unknown-answer boundary.
  • Write a phone-first greeting using identity + capability + invitation.
  • Publish the version before ordering or reservation workflows are added.
Phone-first: no more than three choices, one requested detail per turn, short sentences, and the question last.
10:00 to 14:00

📞 Order Challenge: Let It Fail

  • One volunteer calls the shared agent on speakerphone and tries to place a realistic order.
  • Everyone captures the caller’s exact request and the agent’s exact failure.
  • We do not rescue the agent. The failure reveals the workflow we need to build.
14:00 to 23:00

📲 Repair Round: Take, Confirm, and Text the Order

  • Collect fulfillment method, items, quantities, options, special instructions, name, and callback number one detail at a time.
  • Read back the complete order and get explicit confirmation.
  • Send a structured text message to the kitchen test number.
  • Repeat the exact order call and verify both the spoken confirmation and the kitchen text.
Important boundary: “Your request was sent to the kitchen” is not the same as “Your order was accepted.” Do not collect payment card details in this exercise.
23:00 to 29:00

📖 Menu Power-Up

  • Add the restaurant’s approved menu page or menu document.
  • Test one question the menu can answer and one question it cannot verify.
  • Answer from approved truth, never guess, and offer the next useful action when information is missing.
  • Update your own agent’s knowledge and unknown-answer behavior.
29:00 to 33:00

💥 Break the Bot: 12-Person Reservation

  • One volunteer asks the shared agent for a reservation for 12 people.
  • The whole room listens for the exact point where the unconfigured workflow breaks.
  • We diagnose the missing information and routing rules before changing the agent.
33:00 to 40:00

🔀 Reservation Routing Repair

  • Ask for party size, date, time, name, and callback number, one detail at a time.
  • For 1 to 4 guests, text the approved OpenTable link without claiming a booking exists.
  • For 5 or more guests, transfer to the manager with the collected context.
  • If transfer fails, preserve the details and offer a manager callback.
Warm transfer: reason + collected context + confirmed destination.
40:00 to 43:00

🏆 Final Boss Retest

  • The same volunteer repeats the exact 12-person reservation request.
  • Success means the agent gathers the details, transfers with context, and never invents a reservation.
  • If time allows, test the 1-to-4 guest OpenTable branch too.
43:00 to 45:00

🎉 Close and Continue

  • Name the ordering repair and the reservation repair.
  • Apply the same workflow patterns to your own agent.
  • Within 48 hours, run five more tests, include two adversarial tests, and improve one repeated failure.

Your Build Sheet

1. Restaurant and Goal

My restaurant is ______. The caller outcome is ______.

2. Order Intake

I will collect items, quantities, options, instructions, name, and ______.

3. Order Confirmation

Before texting the kitchen, the agent will read back ______ and ask ______.

4. Approved Menu

It may answer from ______. If an answer is missing, it should ______.

5. Reservation Route

For 1 to 4 guests, ______. For 5 or more guests, ______.

6. Honest Tool Claim

The tool confirmed ______, so the agent may say ______, but not ______.

Patterns to Keep

Confirmed Order

“I have one margherita pizza with extra basil for pickup under Maya. Should I send this order request to the kitchen?”

Honest Tool Result

“Your order request was sent to the kitchen. I have not received confirmation that the kitchen accepted it yet.”

Unknown Menu Answer

“The approved menu does not confirm whether that sauce contains peanuts. I can connect you with the restaurant to verify.”

Large-Party Handoff

“For a party of 12, I’ll connect you with the manager and pass along your requested date, time, name, and callback number.”

A production voice agent succeeds on the normal call, fails safely on the unusual call, and hands off cleanly on the call it should not handle.
