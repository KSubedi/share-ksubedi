1. Website strategy

Every page should answer one primary question, make one important promise, provide concrete proof, and lead to one next action.

01

Lead with outcomes

Start with what the user can accomplish. Introduce architecture only when it explains privacy, cost, speed, or control.

02

Make local-first tangible

Show what stays on the computer, when anything goes online, and how the user remains in control.

03

Demonstrate, do not merely claim

Use short product recordings, interface screenshots, workflow examples, diagrams, benchmarks, and clearly scoped comparisons.

04

Speak to hardware reality

Give visitors a useful path whether their computer is best suited to local, hybrid, or online model execution.

05

Build trust before signup

Explain security boundaries, approvals, data handling, model routing, and account requirements in plain language.

06

Keep conversion simple

Use a consistent primary action such as “Request access” with a contextual secondary action such as “See how it works.”

Core narrative: TurnPanel is the private agent environment that works across your computer, files, models, memory, voice, and devices. It starts local, reaches online when useful, and becomes better as you teach it.

3. Core page outlines

The following pages form the initial marketing site. Each has a distinct conversion job and should avoid duplicating the homepage word for word.

01
Primary conversion page

Homepage

Give a new visitor the complete story in a fast, visual sequence.

Audience: Developers, power users, founders, privacy-conscious professionals, and curious early adopters.
Primary message: Your private agent environment, everywhere.
Primary CTA: Request access.
Secondary CTA: Watch TurnPanel work.
Required proof: Short product demo, interface screenshots, local versus online indicator, and concrete workflow examples.

Recommended section order

  1. Hero: One-line promise, product visual, request-access CTA.
  2. Workflow reel: Files, computer control, memory, search, voice, and remote access in one short sequence.
  3. Why TurnPanel: Local-first context, all-in-one environment, durable memory, model choice.
  4. How it works: Local by default, online when chosen, transparent user approvals.
  5. Use-case tiles: Research, development, documents, automation, personal operations.
  6. Hardware paths: Local, hybrid, and online recommendations.
  7. Privacy summary: What stays local and what can leave the device.
  8. Final conversion: Invite-only explanation and request-access form.
02
Product understanding

Product and capabilities

Turn the all-in-one claim into a clear map of what TurnPanel can actually do.

Audience: Visitors evaluating product depth.
Primary message: One environment connects agents, models, files, tools, memory, voice, and automation.
Primary CTA: Explore workflows.
Required proof: Feature screenshots, short clips, supported file types, action approval examples, and integration examples.

Recommended sections

  • Full computer control with visible approval boundaries.
  • Semantic understanding of files and documents.
  • Durable memory and automated personalization.
  • Web search, page reading, and image discovery.
  • Local and online model support.
  • Voice interaction and dictation.
  • Reusable skills, scripts, and scheduled work.
  • Remote access through the mobile PWA.
  • Built-in OpenAI-compatible local gateway.
03
Core differentiator

Local-first and hybrid AI

Explain the architecture through privacy, cost, speed, and model quality.

Audience: Privacy-conscious users, local AI enthusiasts, cost-sensitive teams, and users with mixed hardware.
Primary message: Start local, escalate online only when it improves the result.
Primary CTA: Find my ideal mode.
Required proof: Routing diagram, example task routes, hardware guidance, model/provider controls, and token-cost examples.

Recommended sections

  • Three modes: local, hybrid, and online.
  • What each mode changes and what remains local.
  • Hardware profiles and recommended setups.
  • Task examples that stay local versus escalate online.
  • How hybrid routing can reduce online token usage.
  • Provider choice, ZDR-compatible configurations, and user controls.
  • Built-in gateway for connecting local models to other apps.
04
Trust page

Security and privacy

Make TurnPanel's boundaries understandable enough that users can make an informed decision.

Audience: Individual buyers, technical evaluators, security teams, and enterprise prospects.
Primary message: Your context is local, online access is explicit, and consequential actions remain visible.
Primary CTA: Read the security model.
Required proof: Data-flow diagram, storage locations, permission model, network behavior, provider-retention notes, and security documentation.

Recommended sections

  • A plain-language “what stays local” summary.
  • Data categories: files, memory, prompts, credentials, telemetry, and model requests.
  • Action approval and destructive-operation safeguards.
  • Online model routing and zero-data-retention caveats.
  • Encryption, credential storage, access controls, and remote access.
  • Update and vulnerability-response process.
  • Enterprise controls that exist now versus planned capabilities.
Content rule: Avoid absolute claims such as “nothing ever leaves your computer” when web search, online models, integrations, or remote access are enabled. State the exact boundary for each mode.
05
Compounding value

Memory and personalization

Show how TurnPanel becomes more useful over time without turning personalization into a privacy concern.

Audience: Professionals tired of repeatedly re-explaining context.
Primary message: Teach your agent once, then benefit across future work.
Primary CTA: See how memory works.
Required proof: Before-and-after workflow, memory review interface, edit and forget controls, and examples of safe personalization.

Recommended sections

  • The problem with stateless assistants.
  • What TurnPanel can remember: preferences, projects, decisions, relationships, and workflows.
  • Automatic learning versus explicit instructions.
  • How users inspect, correct, and delete memories.
  • How local storage changes the privacy model.
  • Examples of compounding value across days and weeks.
  • How repeated procedures become skills or automations.
06
Market education

Comparison page

Help visitors choose an agent architecture, not merely compare feature checkboxes.

Audience: Visitors comparing TurnPanel with Claude Cowork, coding agents, chat apps, and do-it-yourself local stacks.
Primary message: TurnPanel combines local context ownership with flexible model execution and full agent tooling.
Primary CTA: Request access.
Required proof: Cited comparison table, publication dates, methodology, limitations, and links to source policies.

Comparison dimensions

  • Where context and memory are stored.
  • Local, hybrid, and online model options.
  • Computer control and action approvals.
  • File and document understanding.
  • Voice, remote access, automations, and gateways.
  • Provider freedom and cost model.
  • Data-retention choices and account requirements.
Maintenance rule: Date and source every named competitor claim. Revalidate the page before major campaigns because product behavior and policies change quickly.
07
Audience relevance

Use-case pages

Build focused landing pages around valuable jobs instead of creating one long generic features list.

Initial audiences: Developers, founders and operators, researchers, document-heavy professionals, and local AI power users.
Primary message: TurnPanel connects the full workflow, not just the chat response.
Primary CTA: Try this workflow.
Required proof: End-to-end recordings, realistic artifacts, time saved, and the exact tools involved.

Reusable page template

  1. Audience-specific problem and desired outcome.
  2. One hero workflow shown end to end.
  3. Three supporting workflows.
  4. How files, memory, models, and tools work together.
  5. Privacy and hardware considerations for that audience.
  6. Concrete output examples.
  7. Request-access CTA with relevant onboarding prompt.
08
Commercial evaluation

Enterprise

Translate local-first architecture into organizational control, governance, economics, and employee value.

Audience: Security leaders, IT, AI platform teams, operations leaders, and innovation teams.
Primary message: Give employees capable agents without surrendering organizational context or model governance.
Primary CTA: Talk to us.
Required proof: Architecture, deployment options, policy controls, auditability, identity roadmap, support model, and pilot plan.

Recommended sections

  • Enterprise problem: scattered AI tools, repeated context, uncontrolled spend, and data exposure.
  • Private context architecture and deployment boundaries.
  • Model routing, provider policy, and token governance.
  • Access control, audit logs, data residency, and administration.
  • Employee experience and self-evolving approved workflows.
  • Pilot structure, success criteria, procurement, and support.
09
Conversion and activation

Access, download, and onboarding

Set expectations clearly and move approved users from signup to first value with minimal friction.

Audience: Visitors ready to try TurnPanel and invited users ready to install.
Primary message: Request access now, then get a guided path from installation to a working private agent.
Primary CTA: Request access or download.
Required proof: System requirements, supported platforms, setup time, model options, account requirement, release status, and troubleshooting links.

Recommended sections

  • Invite-only release explanation and signup form.
  • Referral loop: each member may invite two people.
  • Supported operating systems and hardware guidance.
  • Choose a first mode: local, hybrid, or online.
  • Installation and account creation.
  • First-run privacy choices and model connection.
  • One guided “aha” workflow using the user's own files or computer.
  • Help, documentation, community, and feedback.

7. Page creation checklist

Strategy

Before writing

  • Name the audience.
  • Choose one page goal.
  • Define one primary CTA.
  • Identify the core objection.
  • List the proof available now.
Copy

While drafting

  • Lead with user value.
  • Use short, specific headings.
  • Separate present features from roadmap.
  • Explain technical terms.
  • Avoid unsupported absolutes.
Design

While building

  • Show the real product early.
  • Use diagrams for architecture.
  • Keep a clear visual hierarchy.
  • Design mobile-first.
  • Repeat the CTA intentionally.
Trust

Before publishing

  • Verify privacy claims.
  • Cite comparisons.
  • Test every link and form.
  • Confirm accessibility.
  • Review security language.
Measurement

After publishing

  • Track CTA conversion.
  • Measure section engagement.
  • Record unanswered questions.
  • Review signup quality.
  • Test one hypothesis at a time.
Maintenance

Ongoing

  • Date sensitive claims.
  • Refresh screenshots.
  • Update system requirements.
  • Revalidate competitors.
  • Promote proven customer stories.
